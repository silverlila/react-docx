## Goal

Remove the dead VS Code extension and the unfinished HTML transformers. Stand up vitest. Record today's writer output for every component folio uses, plus the known-bug cases, as normalized XML snapshots.

Those snapshots are the safety net for units 02–07: any output change they don't intend shows up as a snapshot diff. This unit changes no `src/` behavior. Its only `src/` edits are deleting the two dead transformer files.

### 4. `test/support/docx-xml.ts`: unzip and normalize

```ts
/** The parts the snapshots compare, each pretty-printed one element per line. */
export type DocxXml = Readonly<Record<string, string>>;

/** Unzips with fflate's unzipSync. Keeps every `word/**.xml` part, every `word/_rels/*.rels` part
 *  and `[Content_Types].xml`. Drops `docProps/*`, because core.xml carries render timestamps.
 *  Normalizes, then pretty-prints by replacing every `><` with `>\n<`. */
export function docxXml(bytes: Uint8Array | ArrayBuffer): DocxXml;
```

The one normalization needed was verified on 2026-11-03. External hyperlink relationship ids are random on every render, for example `r:id="rId1xa1eexpwpt5bs6pgchwz"` in `word/document.xml` and the matching `Id="…"` in `word/_rels/document.xml.rels`.

Replace each such id with `rIdLink1`, `rIdLink2`, … in order of first appearance in `word/document.xml`. Apply the same mapping in the rels file and in any header or footer part that uses it. The id pattern is `rId` followed by 20 or more characters from `[a-z0-9-]`. docx.js's own sequential ids (`rId1`…`rId9`) are short, so the pattern doesn't touch them.

Everything else was checked and is stable across repeated renders in one process: image media names (content hashes), `wp:docPr id`, `r:embed`, `w:numId`, and bookmark `w:id`. Do not normalize anything else. Normalizing more would hide real changes.

### 5. `test/support/cases.tsx`: the characterization cases

Every case is a full `<Document><Section>…</Section></Document>`. A 1×1 PNG for images:

### 6. `test/characterization.test.tsx`

For every case: `docxXml(await renderToBuffer(element))`, then `expect(xml).toMatchSnapshot()`, with one `test` per case named after it. For cases with a `bug`, prefix the test name with `[bug] ` so the snapshot file shows which ones are expected to change.

Add one more test, `"output is stable across two renders"`. It renders every case twice and asserts that the two `docxXml` results are equal. This is what proves the normalization in Change 4 is enough.

Run `pnpm test -- -u` once to write the snapshots. Then run `pnpm test` again with no flag; it must pass.

## Watch out

- `docx` is a devDependency and a peer dependency, so tests import it directly. React is 18.3.1 in `node_modules`, which is the only line `src/` supports until unit 02.
- Do not edit `src/` beyond the two deletions. A "small fix" here would get baked into the snapshots as if it were the baseline.
- The snapshot file is large. That is intended: it is the review surface for unit 04.
- `examples/*.docx` files exist locally, untracked. The `.gitignore` line hides them. Do not delete them.
